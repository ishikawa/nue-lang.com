Nue is designed for reliable software: small grammar, deterministic parsing, and safety-first semantics.

## Project layout

The deployable website is intentionally scoped to this directory:

```text
site/
  src/
    pages/
    layouts/
    styles/
```

Deploy only `site/` when publishing to platforms such as GitHub Pages.

## Local setup

```bash
cd site
npm install
npm run dev
```

## Language Snapshot

This snapshot tracks the current design in `$HOME/Developer/Workspace/nue/DESIGN.md`.

### Syntax and parsing

- Grammar is intentionally small and deterministic.
- EOL is a real syntax token; parser behavior is strict by default.
- Automatic EOL insertion exists, but only under explicit tokenizer rules.
- `?:`, `?.`, and `??` are not part of the language. Use `if` expressions and `Option` APIs.

### Ownership and memory

- Ownership is explicit: use `move` and `copy` where ownership changes.
- Function arguments are borrow-by-default; `own` consumes, `inout` is exclusive.
- `ref`, `str`, and `slice` are **NonStorable** views. They can be used temporarily, not stored.
- Memory management is GC-less by default with compiler-inferred lifetimes.
- Flexible shared/cyclic patterns are handled through explicit library/runtime mechanisms.

### Types and abstraction

- `const expr` supports compile-time evaluation (type-level and value-level contexts).
- Const generics are supported via const parameters.
- Protocols support associated types and default implementations.
- Opaque result types are available through `some <constraint>` in return position.

### Example

```ruby
message = if weight <= limit then "OK" else "Over limit"

name: Option[StringLiteral] = adventurer.dog.and_then { _.name }
title: StringLiteral = name.or_default("Untitled")
```
